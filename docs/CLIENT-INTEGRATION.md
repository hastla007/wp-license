# Product plugin client integration

> **Where the client belongs.** The core plugin of each product is free, ungated and published on WordPress.org. It must not contain this client, any entitlement check, a custom updater or any call to the license server. Bundle `LicenseClient` only in the separate premium add-on plugin that is sold and delivered from the shop.

How a product plugin talks to the license server with `WPLC\Client\LicenseClient` (`src/Client/LicenseClient.php`). The class is implemented and unit-tested for request signing and response verification; the full flow against a running server is not yet verified in a shop. The endpoints are specified in [API-V1.md](API-V1.md).

## What the class does and does not do

It does: activation, signed requests, verification of signed responses, entitlement check, update check, deactivation, storing the installation credentials.

It does not: settings screen, caching of entitlements, feature gates, hooking into the WordPress updater, downloading or checking the ZIP. These belong to the product plugin.

Copy the file into the product plugin under the product's own namespace. Its error messages use the text domain `wp-license`; change it to the product's text domain when vendoring, otherwise the messages stay English.

## Constructor

```php
new LicenseClient( string $server_url, string $product_key, string $product_version, string $option_key )
```

- `$server_url`: site URL of the license server. Must be `https`, without credentials, query or fragment; otherwise every call returns `wplc_configuration_invalid` or fails.
- `$product_key`: the stable product key from the server catalog, for example `affiliate-captain`.
- `$product_version`: installed version of the product plugin.
- `$option_key`: name of the option that holds this product's credentials. Use one per product.

## Methods

All methods return the verified data array or a `WP_Error`.

| Method | Purpose |
| --- | --- |
| `activate( string $license_key, string $environment = 'production', string $staging_parent_installation_id = '', bool $force = false )` | Activate this site |
| `check_entitlements()` | Current license status and feature rights |
| `check_update()` | Ask for a newer version |
| `deactivate()` | Release this site's activation and delete the stored credentials |
| `LicenseClient::verified_data( array $envelope, string $secret, string $expected_nonce = '', bool $require_payload = false )` | Static, pure verification of a response envelope (used internally; useful in tests) |

### `activate()`

- `$environment`: `production`, `staging` or `development`. A staging activation needs the installation ID of its live site in `$staging_parent_installation_id`. The server accepts `development` only for local site URLs.
- **Returns the existing activation when the stored credentials are valid:** if credentials are stored and belong to the same license key (or were stored before the key hash existed), `activate()` first calls `check_entitlements()`. If that succeeds, its result is returned and no new activation is created, so a repeated click does not use up another site slot. In that case the result has the shape of an entitlement check.
- `$force = true` skips this and always creates a new installation ID and secret. Use it when the customer deliberately re-activates, for example after entering a different key.
- A new activation sends the license key once. The key itself is not stored, only its SHA-256.
- On the server, a new activation for the same site URL on the same license replaces the old one instead of occupying a second slot.

### Stored option

`activate()` writes one non-autoloaded option (`$option_key`):

| Field | Content |
| --- | --- |
| `installation_id` | UUID generated by the client |
| `installation_secret` | 64 hex characters, generated by the client; signs all later requests |
| `activation_id` | Activation ID on the server |
| `license_key_hash` | SHA-256 of the normalized license key |
| `signed_payload` | `1` once the server has sent `payload`; from then on responses without it are rejected |

Never log or display `installation_secret`. If the option cannot be saved, `activate()` returns `wplc_credentials_not_saved` although the server has created the activation.

### Requests

Authenticated calls send `X-WPLC-Installation-Id`, `X-WPLC-Timestamp`, `X-WPLC-Nonce` and `X-WPLC-Signature`. The signature is HMAC-SHA256 with the installation secret over `METHOD\nroute\ntimestamp\nnonce\nsha256(body)`. Requests use a 20 second timeout, TLS verification and no redirects.

### Response verification

Every successful response is an envelope:

```json
{
  "data": { },
  "signature": "…",
  "payload": "{\"data\":{…},\"nonce\":\"…\"}",
  "payload_signature": "…"
}
```

- `payload` is the exact JSON string the server signed; `payload_signature` is its HMAC-SHA256 with the installation secret. The client checks the signature over the received bytes, then decodes `payload` and compares `nonce` with the request nonce (for activation: with the installation ID it just generated). The returned data comes from `payload`, not from `data`.
- `data` and `signature` are the older form, where the client has to re-encode `data` to check it. The client falls back to it only when `payload` is absent and the stored `signed_payload` flag is not set.
- Errors: `wplc_signature_invalid`, `wplc_nonce_mismatch`, `wplc_response_invalid`. HTTP errors carry the server's error code and message with the status in the error data.

### Entitlements

`check_entitlements()` returns `license_status`, `paid_until`, `site_limit`, `site_count`, `environment`, `entitlements` (key → value), `server_time` and `cache_expires_at` (14 days ahead). Cache the result in the product plugin and gate only premium features on `entitlements`; keep the plugin's basic functions working when the server cannot be reached.

### Update check and download

`check_update()` returns either `update_available: false` or:

`update_available`, `product_key`, `version`, `package_url`, `sha256`, `requires_php`, `requires_wp`, `tested_wp`, `release_notes`, `download_expires_at`.

`package_url` is a one-time link on the license server. The class does not download anything. The product plugin has to pass the data to the WordPress updater (`pre_set_site_transient_update_plugins`, `plugins_api`) and verify the SHA-256 of the downloaded ZIP before installation (for example in `upgrader_pre_download`). The link is valid for 10 minutes and works once; request a fresh one right before downloading.

### `deactivate()`

Sends a signed `DELETE /wplc/v1/activations/{activation_id}`. The stored option is deleted only after the server's signed confirmation. On the server, the staging site linked to a live site is deactivated together with it.

## Example

```php
use WPLC\Client\LicenseClient; // Adjust to the namespace you vendored the class under.

$client = new LicenseClient(
	'https://licenses.example.com',
	'affiliate-captain',
	AFFILIATE_CAPTAIN_VERSION,
	'affiliate_captain_license'
);

// Settings form submitted with a license key.
$result = $client->activate( $license_key ); // Pass true as 4th argument to force a new activation.
if ( is_wp_error( $result ) ) {
	add_settings_error( 'affiliate_captain', $result->get_error_code(), $result->get_error_message() );
	return;
}

// Twice daily: refresh the cached rights. Keep the old cache when the server is unreachable.
$rights = $client->check_entitlements();
if ( ! is_wp_error( $rights ) ) {
	set_transient( 'affiliate_captain_rights', $rights, 14 * DAY_IN_SECONDS );
}

// Feature gate.
$rights  = get_transient( 'affiliate_captain_rights' );
$has_api = is_array( $rights ) && ! empty( $rights['entitlements']['affiliate.extended_api'] );

// Update check, e.g. inside pre_set_site_transient_update_plugins.
$update = $client->check_update();
if ( ! is_wp_error( $update ) && ! empty( $update['update_available'] ) ) {
	// Hand $update['version'], $update['package_url'] to WordPress and
	// compare hash_file( 'sha256', $zip ) with $update['sha256'] before installing.
}

// "Remove license from this site".
$client->deactivate();
```

Entitlement keys are listed in [ENTITLEMENTS.md](ENTITLEMENTS.md).

## Known gaps

- `check_entitlements()` sends only `product_version`. The server also stores `wp_version` and `php_version` from that request, so both are overwritten with empty values after the first check.
- No product plugin uses this version of the class yet; see [CLIENT-REPOS.md](CLIENT-REPOS.md).
